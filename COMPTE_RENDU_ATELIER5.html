1.Contexte, préparation et premier constat

À l'Atelier 4, l'API LogiAI a été testée (52 tests), protégée par clé API (X-API-Key) et appelée par une page web. L'objectif de l'Atelier 5 est de la rendre transportable : l'API et la page tournent chacune dans un conteneur, et une seule commande démarre l'ensemble.

1.1 Vérifications initiales (Docker Desktop WSL2, modèle et pytest)

Depuis la racine du projet contenant logiai/, web/, data/, models/ et .env, nous vérifions que le démon Docker Linux répond sans erreur, que les 52 tests de l'Atelier 4 passent au vert et que les artefacts du modèle (models/model.joblib et models/model_info.json) existent avant le build.

1.2 Premier constat : « ça ne marche que chez vous »

Ce que le projet supposeQui le garantit aujourd'hui (sans Docker)Qui le garantit avec Docker & Compose
Une version de Python (3.11) et des bibliothèques compatibles avec model.joblib Vous, avec .venv et requirements.txt L'image Docker (FROM python:3.11-slim + pip install)
Le fichier .env avec les deux clés (LOGIAI_API_KEY, LOGIAI_ADMIN_KEY) Vous env_file: .env injecté à l'exécution (hors de l'image)
Un modèle entraîné dans models/ (model.joblib, model_info.json) Vous, avec python -m logiai.train Empaqueté dans l'image (COPY) et monté en volume (./models:/app/models)
Deux terminaux : uvicorn (port 8000), puis python -m http.server 5500 Vous, manuellement dans deux terminaux Une seule commande : docker compose up -d --build
Phrase synthèse

« Si je donne mon dossier à un camarade, il doit installer Python 3.11, créer et activer un environnement virtuel .venv, installer requirements.txt, créer son propre fichier .env avec deux clés, générer les données (python -m logiai.dataset), entraîner le modèle (python -m logiai.train), puis ouvrir deux terminaux pour lancer uvicorn sur le port 8000 et python -m http.server 5500 pour la page web. »

2.2 Ports, réseau et les trois sens de localhost

8001:8000 se lit hôte:conteneur : l'API écoute sur le port 8000 dans son conteneur, et Windows l'atteint sur le port 8001. Pour que l'API soit joignable depuis l'extérieur de son conteneur, Uvicorn doit écouter sur 0.0.0.0 (avec 127.0.0.1, seul l'intérieur du conteneur pourrait lui parler).

Où êtes-vous ?localhost (127.0.0.1) désigneComment joindre l'API ?
Dans votre navigateur, sur WindowsVotre machine Windowshttp://localhost:8080/api/... (via Nginx) ou http://localhost:8001 (direct)
Dans le conteneur apiCe conteneur api lui-mêmehttp://127.0.0.1:8000/health (utilisé par le healthcheck)
Dans le conteneur webCe conteneur web lui-mêmePar son nom de service DNS Docker : http://api:8000/

FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt
COPY logiai/ ./logiai/
COPY data/ ./data/
COPY models/ ./models/
ENV LOGIAI_HOME=/app
EXPOSE 8000
CMD ["uvicorn", "logiai.api.main:app", "--host", "0.0.0.0", "--port", "8000"]

Ordre des couches : requirements.txt et pip install sont placés en premier pour être mis en cache tant que les dépendances ne changent pas. Dans logiai/config.py, ROOT = Path(os.getenv("LOGIAI_HOME", ...)) lit LOGIAI_HOME.

4.Sprint 1 — La page web dans un conteneur Nginx

Nginx sert la page statique web/index.html sur le port 80 (publié en 8080 sur Windows) et relaie tous les appels commençant par /api/ vers le service FastAPI http://api:8000/.

4.1 Les trois fichiers du Sprint 1

1. Modification de web/index.html (une ligne) :

const API_URL = '/api/v1/predict';

2. nginx/default.conf :

server {
    listen 80;
    server_name localhost;

    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://api:8000/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}

3. web/Dockerfile :

FROM nginx:alpine
COPY web/index.html /usr/share/nginx/html/index.html
COPY nginx/default.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
Rôle du slash final dans proxy_pass

Le slash final de proxy_pass http://api:8000/; indique à Nginx de retirer le préfixe /api/ : un appel à /api/v1/predict arrive ainsi à FastAPI sous la forme /v1/predict.

4.2 Chemin emprunté par /api/v1/predict de la page à FastAPI

  1. Navigateur (Windows) : depuis la page ouverte sur http://localhost:8080, fetch('/api/v1/predict') envoie une requête POST http://localhost:8080/api/v1/predict avec l'en-tête X-API-Key.
  2. Port publié (8080:80) : Docker redirige la requête vers le port 80 du conteneur logiai-web (Nginx).
  3. Interception et réécriture Nginx : le bloc location /api/ capte la requête, retire le préfixe /api/ grâce au slash final de proxy_pass http://api:8000/;, et résout le nom api via le DNS interne du réseau Docker Compose.
  4. Relais vers FastAPI : Nginx transmet POST http://api:8000/v1/predict au conteneur logiai-api en conservant X-API-Key et en ajoutant Host, X-Real-IP et X-Forwarded-For.
  5. Réponse : FastAPI vérifie la clé, calcule la probabilité de retard et renvoie le JSON 200 OK à Nginx, qui le renvoie au navigateur.

5.Sprint 2 — Docker Compose, healthcheck et volumes

5.1 Fichier docker-compose.yml

services:
  api:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: logiai-api
    ports:
      - '8001:8000'
    env_file:
      - .env
    environment:
      LOGIAI_HOME: /app
    volumes:
      - ./models:/app/models
      - ./data:/app/data
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/health')"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 10s

  web:
    build:
      context: .
      dockerfile: web/Dockerfile
    container_name: logiai-web
    ports:
      - '8080:80'
    depends_on:
      api:
        condition: service_healthy

Étape 8 — Casser puis réparer (docker compose stop api / start api)

Lorsque l'API est arrêtée (docker compose stop api), Nginx ne peut plus joindre http://api:8000/ et renvoie une erreur de passerelle 502 Bad Gateway (ou 504 Gateway Time-out) en HTML. Côté page web, reponse.json() échoue sur ce HTML et déclenche le bloc catch qui affiche : API injoignable ou requête bloquée (CORS). Vérifiez qu'uvicorn est lancé et regardez la console F12. Après docker compose start api, le service repasse healthy et la page refonctionne immédiatement.

Étape 9 — Voir le volume (/app/models)

Le montage ./models:/app/models relie directement le dossier de Windows au conteneur : un nouveau model.joblib ré-entraîné sur Windows est vu sans reconstruire l'image. En revanche, logiai/ n'étant pas monté en volume mais copié par COPY, toute modification du code Python nécessite docker compose up -d --build.

6.Décisions d'architecture (ADR 004) et Questions

6.1 Résumé de l'ADR 004 (docs/adr/004-docker.md)

  • Décision 1 — Le modèle est-il copié dans l'image (COPY) ou monté en volume ?
    Choix retenu : les deux (COPY models/ ./models/ dans le Dockerfile + volume ./models:/app/models dans docker-compose.yml).
    Ce que l'autre option ferait perdre : avec COPY seul, chaque ré-entraînement (python -m logiai.train) obligerait à reconstruire toute l'image Docker ; avec un volume seul, l'image distribuée seule serait dépourvue de modèle et renverrait 503.
  • Décision 2 — Quels ports sont publiés : 8080 seulement, ou aussi 8001 ?
    Choix retenu : 8080 et 8001 en développement/TP ; 8080 uniquement (ou 443 HTTPS) en production.
    Ce que l'autre option ferait perdre : sans 8001 en TP, on perd l'accès direct à Swagger UI (http://localhost:8001/docs) ; avec 8001 ouvert en production, un visiteur peut contourner Nginx et attaquer directement Uvicorn/FastAPI (/docs, /v1/...) sans passer par le reverse proxy.

7. Cinq questions de compréhension et Ticket de sortie

  1. Quelle différence entre une image et un conteneur ? Une image est un modèle immuable en lecture seule construit par couches à partir d'un Dockerfile ; un conteneur est une instance isolée en exécution créée à partir de cette image, avec une fine couche inscriptible éphémère.
  2. Pourquoi le navigateur appelle-t-il /api/v1/predict et non api:8000 ? Le navigateur tourne sur Windows, hors du réseau Docker où seul le DNS interne connaît le nom api. Le chemin relatif /api/v1/predict appelle la même origine (localhost:8080, sans CORS), et Nginx relaie vers http://api:8000/v1/predict.
  3. Pourquoi depends_on seul ne suffit-il pas, et que change service_healthy ? depends_on seul attend seulement le démarrage du conteneur, pas que FastAPI ait chargé le modèle et écoute sur 8000. condition: service_healthy attend que le healthcheck sur /health renvoie 200 OK.
  4. Pourquoi .env est-il dans .dockerignore et dans env_file ? .dockerignore empêche que les clés soient gravées dans une couche de l'image au moment du build, tandis que env_file les injecte uniquement en mémoire à l'exécution du conteneur.
  5. Pourquoi /health doit-il rester public ? Parce que le healthcheck de Docker interroge http://127.0.0.1:8000/health sans clé API : s'il recevait 401, l'API serait déclarée unhealthy et le conteneur web ne démarrerait jamais.
